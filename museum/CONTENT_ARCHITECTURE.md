# A museum with deeper rooms

The existing sculptures, landing composition, horizontal rail, plinth rooms, transitions and motion preferences are the preserved design baseline. The upgrade opens new rooms behind those objects: independent project cases, the notebook, an editorial timeline and an isolated travel exhibition.

## Evidence and authorship

The local audit covers source code, Git history, dated reports and output verification. It separates direct engineering evidence from owner-reported scope, team contributions, prototypes and unverified chronology. Private evidence paths, raw reports, exact client counts, prompt libraries and confidential media stay in Atlas’s private editorial source. Public source contains curated prose, generalized diagrams and reviewed assets.

The minimum case structure is a problem, role, personal contribution, architecture, technical decisions, evidence, limits and lessons. Existing professional summaries and previously approved aggregate research metrics provide the public baseline. Medical image and client-media restrictions apply independently of code ownership.

## Publication boundary

Atlas editorial records have independent visibility, rights and exact-revision review. Saving changes invalidates approval. A sanitized, field-allowlisted snapshot is previewed and exported into a separate static content model. The website receives no jobs, mail, credentials, applicant database or raw research paths.

StarMap is reused under MIT for the travel exhibition. Its normal fictional public samples and external personal data remain separate from a third approved-public mode. Only explicitly confirmed records and individually reviewed, metadata-stripped media enter that build. Visitors receive static published data and read-only controls.

## Content state

Verified project areas include visual-data systems, taxonomy, aesthetic-image review, infographic and web collection, PanSegAI, local creative software and Atlas.
